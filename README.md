# 🔥 Roast My Repo

An agent that **actually runs your code** and then roasts you with receipts.

Open an issue titled **"roast me"** on your repo. The agent then:
1. downloads the repo onto its own Fly.io Sprite
2. installs, tests and lints it, and digs through the README, commits and issues for evidence
3. replies with a roast where every burn links to the exact file and line
4. fixes the worst offence, re-runs the check to prove the fix works, and opens a PR

> **README lies**: Your README says `npm run start-dev`. package.json has never heard of it. Fiction belongs on Wattpad.
> 🛠️ Rename the script or fix the README so new contributors don't rage-quit on step one.

## Why it can't be a chatbot
- **It runs your code.** The Sprite is a real, isolated Linux box, so it can `npm install`, `pytest` and `go vet` your repo without risking your laptop.
- **No made-up burns.** `checks.py` collects facts with plain code. The model only writes jokes about findings it was given, and every link is generated by code.
- **No tokens on the box.** GitHub and OpenRouter both go through **Sprites connectors**.

## Files
| File | Job |
|---|---|
| `roast.py` | Entry point: one-off roast from the CLI, or `serve` mode that watches for "roast me" issues |
| `checks.py` | The inspection: hygiene, README commands that don't exist, TODOs, god files, lazy commits, ghosted issues; with `--run`: setup/test/lint for Python, Node, Go, Rust |
| `roaster.py` | Turns findings into the roast; crispiness score computed in code |
| `fixer.py` | Fixes one thing: ruff/gofmt/.gitignore without AI, Claude Code for real bugs, a one-file LLM edit as fallback. Verifies before opening a PR |
| `github.py` | GitHub via the connector (download, comment, PR through the contents API, so no `git push` credentials needed) |
| `llm.py` | OpenRouter via the connector |

Standard-library Python only. No `pip install` needed for the agent itself.

## Setup on a Sprite
1. In the Sprites dashboard, add a **GitHub** connector and an **OpenRouter** connector, and grant your Sprite access to both.
2. Copy this folder onto the Sprite. Then:
   ```bash
   curl https://api.sprites.dev/v1/gateway/list     # find your connection IDs
   export GITHUB_BASE=https://api.sprites.dev/v1/gateway/github/<conn_id>
   export LLM_BASE=https://api.sprites.dev/v1/gateway/openrouter/<conn_id>/api/v1
   ```
3. Roast something:
   ```bash
   python3 roast.py you/your-repo                 # static roast only
   python3 roast.py you/your-repo --run --pr      # run the code, roast, fix, open PR
   python3 roast.py serve --run                   # watch your repos for "roast me" issues
   ```
   Set `ROAST_REPOS=you/a,you/b` to limit which repos `serve` watches. By default it watches every repo you can push to.

Options: `ROAST_MODEL` (default `anthropic/claude-sonnet-4.5`), `FIX_AGENT=auto|claude|llm|none`, `POLL_SECONDS`. `LLM_BACKEND=mock` tests everything without a model.

## Safety
- `--run` executes the repo's code. Only use it on repos you trust (your own), and only on a Sprite.
- Code running on the Sprite could, in principle, call the same connectors the agent uses. Restrict the GitHub connector's allowed endpoints to the ones the agent needs. Better still, run untrusted repos on a second Sprite that has no connector access.
- Only opens PRs on repos you have push access to. Never forks and spams strangers.
- Roasts the code, never the person.
